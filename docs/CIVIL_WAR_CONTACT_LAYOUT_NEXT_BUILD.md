# Next build: a continuous contact line

This is the next mechanics-presentation build after v32's restored assault selector and Union B contact/casualty sources. The current formation feet, ground-Y sorting, combat and saved fall positions are correct for their existing model. Dense overlapping rifle silhouettes remain a separate gap. Astra Max reviewed the current renderer/state/checkpoint code and found no demonstrated benefit from adding a depth tie-break. V32 therefore preserves those files. This plan does not claim an implemented spacing repair.

## Order of implementation

1. Capture matched contact states before changing layout: the normal Gettysburg approach and the reverse flank route, both armies, all eight bearings and mixed uniforms. Preserve overview and close-up images at the same field time, viewport, camera and body scale. Record actual sprite-alpha overlap, visible body count, combat facts, raw feet, footprints and shot origins. Establish which overlap obstructs reading the front rather than assuming all overlap is undesirable.
2. Build an optional renderer layout from immutable simulation figures. For a verified opposing pair, derive the normal between formation centers. Try only a small symmetric backward displacement of the actual melee-front display points, initially capped at 3–4 world pixels per side and contained within the original oriented footprint. Keep every rear rank and formation orientation in place. Introduce bounded tangent staggering only if the matched images show a further benefit. Handle invalid, coincident, off-center or multiple opponents explicitly.
3. Give displayed casualties a continuous handoff before shipping any displacement. Keep a small versioned presentation record of the last displayed offset for each stable formation/figure identity. When an alive figure becomes a casualty, freeze that offset with the saved raw fall position and simulation birth time. Continue using it after contact ends, retreat, turning, resolution and fade. Update the layout when the current visual state is sampled for a checkpoint, even if no draw occurred. An unsaved Scene cache is insufficient.
4. Add bounded optional presentation checkpoint data and restoration. Bind records to policy version, stable identity, current capacity and exact saved simulation time; reject duplicate/nonfinite/out-of-range or stale entries. Missing/invalid new presentation records fall back safely to the accepted unshifted view without rejecting valid combat. Keep the owner-v2 campaign anchor, checksum algorithm and raw combat serialization unchanged. Do not assume that the existing parser accepts additional fields: verify its real producer/consumer behavior and checkpoint ordering first. Every earlier art policy must retain its previous bytes and behavior.
5. Draw bodies and their shadows from the same derived displayed points and ground depth. Preserve raw visual figures, formation centers, hit/selection footprints, standards, fresh and cached firing muzzles, smoke origins, collision, damage, ammunition, orders and AI. Do not mutate `updateFormationVisual`'s cached output or pass displaced points to the volley sampler. Document that displayed feet now differ slightly from their raw simulation anchors.
6. Accept the feature only after measured and visible improvements plus continuity checks. Compare matched snapshots; reject excessive gaps, drifting shadows, changed body scale, clipped rifles, phantom strength loss or a casualty snap. Check pause, reduced motion, contact ending, reformation, simultaneous losses, query switching, first cold draw and immediate re-save before that first draw. Include contact within the lifetime of a previous volley. Finish with public Move/Assault, Save/cold Resume and a further running segment. Record target-device performance and human feedback separately from deterministic checks.

## Acceptance boundary

The feature should improve readability while allowing two bodies/rifles to overlap naturally in a fight. A smaller analytical overlap count alone is not sufficient. The current art's four phases are discrete poses; this layout does not certify physical motion or historical drill. Keep the feature optional until both display continuity and ordinary command play are validated, then review wider battle/default promotion separately.
