# Upgrade 27 — smaller battlefield files, identical visuals

Release 0.29.0. User constraint: proceed only with no real visual degradation.

## Visual acceptance

All 41 battlefield/unit PNGs were losslessly recompressed. **Decoded pixels, resolution, color mode, transparency and every non-IDAT PNG chunk are unchanged.** No images were resized, quantized, converted to a new format or regenerated. Chroma keying, animation frames, atlas coordinates, renderer and combat code remain unchanged.

Three checks establish the image invariants:

1. The encoder compares native decoded pixel bytes and every non-IDAT chunk before accepting a smaller file.
2. An independent Node PNG decoder reconstructs the filtered scanlines and checks their SHA-256 against the original pixel bytes. It also checks the original metadata/chunk hash, dimensions, mode and delivered-file hash for every image.
3. The browser decoded original and repacked versions of all 41 images into native-resolution canvases: **41/41 identical, zero changed RGBA channels**.

An in-game Manassas close-up before and after the change was also **pixel-for-pixel identical across the complete 1280×720 screenshot**. Subsequent unit movement rendered without browser errors. This is exact preservation of the existing art, not a subjective judgment that reduced quality is acceptable.

## Provenance and verification

Atlas manifests and the Manassas ground manifest now record the recompressed file hashes while retaining original-file hashes and adding original-pixel hashes. Dimensions, frame coordinates and historical/art descriptions are preserved. The original files are retained in the rollback and comparison evidence.

`docs/FIELD_PNG_REPACK_2026-09-14.json` is the per-file acceptance manifest. `scripts/test-field-png-repack.mjs` contributes 41 permanent checks to asset validation. `scripts/optimize-field-pngs.py` is the reproducible encoder, requires Pillow, defaults to dry-run, preserves PNG metadata, updates affected atlas/current-ground file hashes and refuses to overwrite its report. Run `--apply` in an isolated copy and verify it before installation. A synthetic transparent-color/metadata fixture also verified atlas hash updates and idempotence.

The existing Manassas byte-hash test initially rejected the changed compression; that failure was retained, then the current-file manifest was updated with both original and new provenance. Its assertion remains intact, supplemented by the stricter pixel-equivalence tests. **Full `npm run validate`: 1,253 tests passed, zero failures.** Production build passed with the existing large-chunk warning. Dedicated asset checks also passed. Logs are retained in the installation evidence.
